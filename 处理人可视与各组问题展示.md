# 处理人可视与各组问题展示

质量看板里已经有两块视图：一张能看见处理人、也能认出归属组；另一张按业务组展示问题。代码仓是 ergon-studio/mindstudio-quality-monitor。

## 处理人可视

DTS 明细把源系统抓到的当前处理人做成一列。姓名和部门拆开，渲染时放在人名下面。

`backend/src/record.rs`

```rust
text("current_handler", "当前处理人"),
derived_text("handler_person_name", "处理人·姓名"),
derived_text("handler_person_dept", "处理人·部门"),
text("subsystem_name", "责任组"),
text("group_name", "归属组"),
```

页面上工号对不上人员目录时，退回 DTS 原始字符串，名字不丢。

`frontend/src/views/dts-view.ts`

```typescript
registerCell("dts-person", ({ values, col }) => {
  const name = text(values, col.name) || text(values, col.name.replace(/_person_name$/, ""));
  if (!name) return `<span class="text-meta">—</span>`;
  const dept = text(values, col.format.sub_field);
  return `<div class="dts-person-cell">${esc(name)}${dept ? `<span class="cell-sub">${esc(dept)}</span>` : ""}</div>`;
});
```

社区 Issue 的处理人是单独一列。没选过的显示「-」。有权限时就地设置。

`frontend/src/views/issues-view.ts`

```typescript
registerCell("issue-owner", ({ row }) => {
  const i = row as Issue;
  const attrs = i.capabilities.can_set_owner
    ? ` data-owner-url="${esc(i.url)}" aria-label="设置处理人"`
    : "";
  const name = i.owner ? esc(i.owner.display_name) : `<span class="text-meta">-</span>`;
  return `<div class="issue-owner"${attrs} data-owner="${esc(JSON.stringify(i.owner))}">${name}</div>`;
});
```

点选后写入 `issue_owners`。作者登录名不会自动变成处理人。清空则删掉这一行。

`frontend/src/views/bind.ts`

```typescript

`backend/src/db/attack.rs`

    r#"INSERT INTO issue_owners (issue_url, person_json) VALUES (?, ?)

```

## 归属可识别

DTS 上有两列组。`责任组` 是抓取带来的 `subsystem_name`。`归属组` 是看板上的人工下拉，QA 日报按这一列累加。空着显示「未指定」。

`frontend/src/views/dts-view.ts`

```typescript
const DTS_GROUP_COLUMN = fixedColumn({ name: "group_name", label: "归属组", cell: "dts-group" });

registerCell("dts-group", ({ values, row, can }) => {
  const no = dtsRowNo(row as DtsRow);
  const group = text(values, "group_name");
  const editable = can("set_dts_group", row);
  if (editable && S.dtsEditingGroupNo === no) {
    const options = (S.me?.assignable_dts_groups ?? [])
      .map((name) => `<option value="${esc(name)}"${name === group ? " selected" : ""}>${esc(name)}</option>`)
      .join("");
    return `<select class="dts-group-select" aria-label="DTS ${esc(no)} 归属组"><option value=""${group ? "" : " selected"}>未指定</option>${options}</select>`;
  }
  const label = group ? esc(group) : "未指定";
});
```

Issue 的组不在原文里。取数时用仓库绑定把单归进业务组，同时带出处理人。

`backend/src/query.rs`

```rust
r#"SELECT i.url, i.group_name, i.project, i.title, i.author_login, i.labels, i.state,
          s.due_at AS manual_due_at, o.person_json
   FROM issues i
   JOIN group_repos gr ON gr.repo = i.project
   LEFT JOIN issue_sla s ON s.issue_url = i.url
   LEFT JOIN issue_owners o ON o.issue_url = i.url
"#
```

没绑定仓库的 Issue 进不了这张列表。已划转的单在落库时保留人工指定的组，不被下一轮仓库绑定盖掉。

## 各组问题展示

首页是业务组总览。每一行一个组，按风险排序。点组名进入该组的问题。

`frontend/src/views/issues-view.ts`

```typescript
<h2>业务组总览</h2>
<p>先判断哪些业务组需要关注，再进入组内从项目、处理人、Label 等角度分析。</p>

const groupRows = S.snap.groups.map((group) => {
  const issues = bugIssuesOf(group.name);
  const overdue = issues.filter((issue) => issue.due_overdue).length;
  // ...
});

<button type="button" class="group-open" data-open-group="${esc(group.name)}">
  <strong>${esc(group.name)}</strong>
</button>
```

组内待闭环只取这个组、并且属于关注范围的 bug 类。

```typescript
export function bugIssuesOf(group: string): Issue[] {
  return (S.snap?.issues ?? []).filter((issue) => issue.group === group && issue.is_bug_class);
}

export function groupIssues(): Issue[] {
  return (S.snap?.issues ?? []).filter((issue) => issue.group === S.viewGroup);
}
```

组内页有「明细」和「统计」两个页签。明细表的列来自 `issues_overview`，其中包含处理人。攻关进展表同样按组一行，点组名也进这组的问题。
